# Datetime SDK Consumer Handoff

## Purpose

This guide is for AI agents working in consumer UI repositories that depend on `@aifabrix/miso-client`.
Use it to migrate local datetime formatting helpers to the shared SDK datetime utilities.

Target consumer repositories:
- `aifabrix-miso` (`packages/miso-ui`)
- `aifabrix-dataplane` (`app-ui`)

## Required SDK Imports

```typescript
import {
  formatDateTime,
  formatDate,
  formatTime,
  createDateTimeFormatter,
  formatLogDateTimeUtcFixed,
  parseIsoTimestampMs,
} from "@aifabrix/miso-client";
```

## Decision Matrix (What to Use)

- Locale-aware date + time display in UI: `formatDateTime`
- Locale-aware date-only display: `formatDate`
- Locale-aware time-only display: `formatTime`
- Repeated list/table rendering: `createDateTimeFormatter`
- Deterministic UTC audit/log/export display (`DD/MM/YYYY, HH:mm:ss`): `formatLogDateTimeUtcFixed`
- Datetime parsing for sort/duration arithmetic: `parseIsoTimestampMs`

## Integration Strategy (Two Tracks)

### Track A: `aifabrix-miso` (`miso-ui`)

1. Locate local datetime helper functions in consumer UI code.
2. Replace helper usage with one of:
   - `formatDateTime(value, options?)`
   - `formatDate(value, options?)`
   - `formatTime(value, options?)`
3. For table/list hot paths, prefer a reusable formatter:
   - `const renderDateTime = createDateTimeFormatter(options);`
4. Keep existing UI labels/text unchanged; replace only formatting logic.
5. Remove obsolete local helper code after all call sites are switched.

### Track B: `aifabrix-dataplane` (`app-ui`)

1. Replace locale display helper usage with `formatDateTime` / `formatDate` / `formatTime`.
2. Replace deterministic UTC log formatter usage with `formatLogDateTimeUtcFixed`.
3. Replace local timestamp parsing helper usage with `parseIsoTimestampMs`.
4. Validate parity for fixed UTC format (`DD/MM/YYYY, HH:mm:ss`) and fallback behavior.

## Codebase Pattern Mapping

### `aifabrix-miso` (`miso-ui`)

Common current patterns:
- Inline `new Date(...).toLocaleString("en-US", ...)`
- Inline `new Date(...).toLocaleString("pt-PT", ...)`
- Local helper `formatTimestamp(...)`

Target replacement:
- Prefer `formatDateTime(...)` for date+time.
- Use `formatDate(...)` or `formatTime(...)` when only one part is displayed.
- For dense tables, create one reusable formatter via `createDateTimeFormatter(...)`.

### `aifabrix-dataplane` (`app-ui`)

Common current patterns:
- `formatShortDateTime(...)` for locale-style display
- `formatLogDateTime(...)` for deterministic UTC logs
- `parseIsoTimestampMs(...)` for timestamps to milliseconds

Target replacement:
- `formatShortDateTime(...)` use-cases -> `formatDateTime(...)` (or `formatDate`/`formatTime` where clearer)
- `formatLogDateTime(...)` use-cases -> `formatLogDateTimeUtcFixed(...)`
- local `parseIsoTimestampMs(...)` import/use -> SDK `parseIsoTimestampMs(...)`

## Behavior Contract to Preserve

- Default locale: browser/runtime locale.
- Default timezone: browser/runtime local timezone.
- Empty values (`null`, `undefined`, empty string, `-`) return fallback (`-` by default).
- Invalid non-empty datetime strings return original trimmed value.
- Invalid numeric/date values return fallback.
- `formatLogDateTimeUtcFixed` always renders UTC in fixed pattern `DD/MM/YYYY, HH:mm:ss`.
- `parseIsoTimestampMs` returns epoch milliseconds, or `0` for empty/invalid input.

## Recommended Options Usage

- Do not force `locale` or `timeZone` unless product requirements require it.
- Use explicit `locale` + `timeZone` for deterministic logs/audit displays if needed.
- Enable `includeSeconds` only where precision is required.

## Migration Verification Checklist

- [ ] All replaced UI call sites still render valid datetime text.
- [ ] Locale-sensitive screens show expected region-specific formatting differences.
- [ ] Timezone override views (if any) still show intended timezone output.
- [ ] Empty and invalid values match contract fallback behavior.
- [ ] Removed helper code has no remaining references.
- [ ] Automated UI/unit tests covering datetime rendering pass.
- [ ] For dataplane log/audit screens, UTC fixed output remains `DD/MM/YYYY, HH:mm:ss`.
- [ ] For dataplane sort/duration flows, parsed millisecond values stay numerically consistent.

## Quick Mapping Example

Before:

```typescript
const value = formatTimestamp(rawTimestamp);
```

After:

```typescript
const value = formatDateTime(rawTimestamp);
```

Before (inline locale formatting):

```typescript
const value = new Date(rawTimestamp).toLocaleString("en-US", {
  month: "short",
  day: "numeric",
  year: "numeric",
  hour: "2-digit",
  minute: "2-digit",
});
```

After:

```typescript
const value = formatDateTime(rawTimestamp);
```

Before (dataplane deterministic UTC log display):

```typescript
const value = formatLogDateTime(rawTimestamp);
```

After:

```typescript
const value = formatLogDateTimeUtcFixed(rawTimestamp);
```

Before (dataplane timestamp parse):

```typescript
import { parseIsoTimestampMs } from "@/utils/dateTime";
const ms = parseIsoTimestampMs(rawTimestamp);
```

After:

```typescript
import { parseIsoTimestampMs } from "@aifabrix/miso-client";
const ms = parseIsoTimestampMs(rawTimestamp);
```

Before (list rendering):

```typescript
rows.map((row) => formatTimestamp(row.createdAt));
```

After (reused formatter):

```typescript
const renderDateTime = createDateTimeFormatter({
  includeSeconds: true,
});
rows.map((row) => renderDateTime(row.createdAt));
```
