## Pre-Execution Decisions (Finalized)
- **New symbols (locked):**
  - `formatLogDateTimeUtcFixed(value, options?)` - deterministic UTC formatter for log/audit/export style output.
  - `parseIsoTimestampMs(value)` - canonical parser returning epoch milliseconds (or `0` for empty/invalid).
- **UTC fixed output contract (locked):**
  - Format: `DD/MM/YYYY, HH:mm:ss`
  - Timezone: UTC
  - Includes seconds always
  - Sub-millisecond ISO fractions are normalized before parse.
- **Fallback contract (locked):**
  - Empty values (`null`, `undefined`, empty string, placeholder `-`) return fallback (`-` by default).
  - Invalid non-empty string input returns the trimmed original input.
  - Invalid numeric/date inputs return fallback for formatter functions.
  - `parseIsoTimestampMs` returns `0` for empty/invalid parse.
- **Compatibility boundary (locked):**
  - Existing locale-first helpers (`formatDateTime`, `formatDate`, `formatTime`, `createDateTimeFormatter`) keep current behavior unchanged.
  - No renames/removals in public API; only additive symbols/typing.

## Evidence From Consumer Fit-Check

- `dataplane app-ui` has centralized helpers, but includes a **fixed UTC log format** (`DD/MM/YYYY, HH:mm:ss`) not fully represented by current SDK locale-first helpers.

## Recommended Best Practices
- **Keep locale-first as default path**: all existing locale helpers should continue to use browser/runtime locale and timezone unless an explicit override is required by business logic.
- **Isolate deterministic UTC formatting**: keep UTC fixed-format behavior in a dedicated formatter function to avoid accidental coupling with locale-first rendering.
- **Preserve fallback contract exactly**: keep empty-value and invalid-value behavior aligned with existing consumer expectations (`-` and trimmed original string where applicable).
- **Maintain no-throw behavior for UI safety**: datetime utilities must never throw in render paths; errors should resolve to deterministic fallback output.
- **Use explicit options for deterministic tests**: pin `locale` and `timeZone` in tests that assert exact strings; avoid brittle full-string assertions for runtime-default locale behavior.
- **Prefer additive API changes only**: add new symbols/options without renaming/removing existing ones to keep migration low risk for current SDK consumers.
- **Document migration by use-case, not by file list**: provide mapping by behavior (`locale display`, `UTC fixed logs`, `timestamp parsing`) so consumer agents can apply it consistently across many call sites.
- **Keep parsing utility single-source**: expose one canonical parse helper in SDK and avoid duplicating parse rules (`sub-millisecond normalization`, placeholder handling) in consumers.

## Risks and Mitigations
- **Risk: behavior drift between locale and UTC paths**  
  Mitigation: keep separate tests per pathway and add parity assertions for shared fallback semantics.
- **Risk: consumer regressions during migration**  
  Mitigation: update handoff checklist with before/after mapping and explicit fallback verification steps.
- **Risk: hidden timezone assumptions in existing UI**  
  Mitigation: require explicit `timeZone` overrides only where fixed-output requirements are documented.
