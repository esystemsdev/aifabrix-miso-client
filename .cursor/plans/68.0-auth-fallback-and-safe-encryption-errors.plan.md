# 68.0 Auth fallback and safe encryption diagnostics

## Purpose and review scope

Validate the TypeScript SDK against the auth/encryption failure paths repaired in
Python `miso-client==5.0.4`. The initial review requested validation and a plan for confirmed problems. The
subsequent user instruction authorized implementation and testing, with emphasis
on E2E tests using the existing `builder/miso-test` application. Implementation
and validation are complete as recorded below; publication remains out of scope.

Reviewed `/home/dev01/aifabrix-miso-client`, `@aifabrix/miso-client` version
**5.0.2**, commit **fb69f838c5ea953aa183b07a605d6cb63be1a193**, on 2026-09-30.
The scope is HTTP authentication strategies, token ownership, encryption API/service
errors, error extraction and console diagnostics. This is not a whole-SDK security
certification or a claim about deployed consumer behavior.

## Confirmed findings

### P1 — client credentials can leave the token-grant endpoint

`src/utils/auth-strategy.ts:43` emits `x-client-id` and `x-client-secret` for
`client-credentials`. `InternalHttpClient.buildAuthStrategyConfig()` passes them
to the ordinary request. The interceptor sees `x-client-id` and skips automatic
token attachment. This contradicts the existing repository security contract.

An Axios-adapter probe through `requestWithAuthStrategy(POST,
/api/security/parameters/encrypt, {methods: [client-credentials]})` observed:

| Header presence   | Result |
| ----------------- | ------ |
| `x-client-id`     | true   |
| `x-client-secret` | true   |
| `x-client-token`  | false  |

The probe used synthetic credentials and made no network request. Preserve the
method name for compatibility if needed, but resolve it to a client token through
the existing owner. Only the configured initial grant may receive client ID/secret.
Keep external-origin credential stripping and managed bootstrap guards intact.

### P1 — controller error data is not sanitized before exposure or console logging

`src/utils/http-error-handler.ts:120` copies `error.response.data` directly into
`MisoClientError.errorBody`. Structured titles/details are also accepted without
redacting echoed secrets. `src/utils/error-extractor.ts:82` returns the raw body
when no structured response exists; `src/utils/console-logger.ts:57` prints it.
Both encrypt and decrypt call that logger in `src/api/encryption.api.ts`.

Eight public encryption-service probes (two operations × local/managed guard ×
RFC/non-RFC bodies) confirmed a synthetic `clientSecret` sentinel survives in
`errorBody` in every case. For the four non-RFC cases, it also reaches console
output. Structured messages/diagnostics must also be tested for echoed credentials;
field-name masking alone does not redact a credential embedded in `detail`.

Sanitize once before constructing public exceptions, and ensure error extraction,
console output and audit/debug layers use the sanitized representation. Reuse
DataMasker, mask known credential/token/encryption payload values, bound untrusted
payload parsing, and do not retain an unsanitized Axios object as a public cause.
Do not weaken the managed runtime's secret non-disclosure contract.

### P2 — configured auth methods are selected once, not retried after a 401

`AuthStrategyHandler.buildAuthHeaders()` returns the first method with available
data. `InternalHttpClient.requestWithAuthStrategy()` builds one config and calls
`executeMethod()` once. There is no response-driven fallback loop. This differs
from Python's wrong-exception-type defect: TypeScript never tries a second request.

Four probes (both method orders × local/managed guard) used real Axios interceptors
and SDK error conversion, with an adapter refusing the first method and accepting
the second. Every probe dispatched only the first method and failed.

Implement ordered attempts for ordinary 401s; return the first success. Resolve
current tokens after invalidation/refresh rather than retaining a rejected token.
Preserve the final safe diagnostics after exhaustion. Do not retry 403/422/429/5xx,
transport failures, cancellation, or typed bootstrap revocation/expiry responses.
Do not replay a request after runtime invalidation.

### P2 — structured errors and extraction discard controller diagnostics

`toConfigErrorResponse()` / `toRfc7807ErrorResponse()` in
`src/utils/http-error-handler.ts:33,48` drop correlation and additional diagnostic
fields. `extractMisoClientError()` in `src/utils/error-extractor.ts:67` only reads
correlation from `errorResponse`; when that object exists, it rebuilds a partial
response instead of consulting the richer body. Response-header correlation is
not promoted into the exception contract.

In all four RFC encryption probes, status and raw `errorBody.code` /
`errorBody.correlationId` survived, but `errorResponse.code`,
`errorResponse.correlationId`, and extracted correlation were absent. Preserve
code, detail, authMethod, controller-disclosed clientIdentity, instance and
correlationId in consistent safe public surfaces. HTTP status must remain
transport-authoritative. Do not invent client identity when it is withheld.

## Differences from the Python diagnosis

- EncryptionService does **not** rewrap transport failures as `EncryptionError` or
  overwrite the controller code with `ENCRYPTION_FAILED`; EncryptionApi logs and
  rethrows the same error. Preserve that existing error-type compatibility unless
  a separately reviewed contract change is necessary. Repair the shared transport,
  typed diagnostics and extraction rather than importing a nonexistent wrapper bug.
- Controller calls already carry `x-client-token` on ordinary bearer attempts.
  The encryption probes observed it present. A missing-header explanation cannot
  be inferred solely from the lack of fallback.
- `tokenRefreshPromise` already coalesces failed token acquisition. A 24-caller
  callback-failure probe produced **one refresh / 24 rejections**. Do not introduce
  another token cache, Redis dependency, or failure cooldown as part of this plan.
- Existing [65.0 transport migration](65.0-application-bearer-transport.plan.md)
  governs any future Bearer-default switch. This repair must retain the current
  normal-endpoint client-token contract and avoid implementing that migration.

1. **Prerequisites (`before-development`)**: complete Before Development; record

   `src/utils/auth-strategy.ts` and `src/utils/internal-http-client.ts` through the
   existing local token owner or managed runtime guard. Preserve public method names;
   never introduce a second credential grant in managed mode.
3. **Fallback (`auth-fallback`)**: share the attempt loop between
   `requestWithAuthStrategy()` and `authenticatedRequest(..., authStrategy)`.
   Requests without an explicit strategy retain current behavior, including encryption.
   Try eligible configured methods in order, at most once per configured entry;
   skip unavailable bearer/API-key values and preserve the existing no-eligible-method
   outcome without adding retries. Rebuild headers case-insensitively for each attempt,
   clearing stale Authorization and client credential/token headers before applying
   the selected method and current application token. Preserve unrelated headers,
   cancellation and caller config without mutation. Never replay consumed stream
   bodies; restrict retries to replayable payloads. Only transport-status 401 enables
   fallback; typed bootstrap codes and runtime invalidation take precedence, including
   `bootstrap_token_expired` even when refresh succeeds. No implicit fallback from a
   user-authenticated call without an explicitly configured alternative.
4. **Diagnostics (`safe-diagnostics`)**: update `src/utils/http-error-handler.ts`,
   `src/utils/errors.ts`, `src/utils/error-extractor.ts`, the applicable ErrorResponse

   for field masking, supplemented by request-scoped known-value redaction: configured
   credentials, actual issued/current tokens, bearer/API-key values, encryption keys,
   plaintext and encrypted references. Capture values before token invalidation without
   retaining raw Axios configs in exceptions or global state. Bound string size,
   traversal depth and collection size, handle cycles, and fail closed on unsafe data.
   Audit metadata is captured separately from exception conversion: apply the same

   Preserve safe diagnostics with transport-authoritative status on every surface;

## Expected Automated Tests

Use real SDK routing/interceptors/conversion and Axios adapters. Do not replace
`request`, `executeMethod`, or the encryption API with a mock at the defect seam.

- Both auth orders × GET/POST × local/managed mode: first ordinary 401 then second
  method succeeds; assert exact attempts, headers and returned data.
- Cover both explicit-strategy entry points, mixed-case/stale auth headers, caller
  config immutability, unavailable methods and non-replayable request bodies.
- Exhaustion retains final status and sanitized diagnostics. Non-401s and network
  failures make one attempt only. Cancellation stops further attempts.
- Actual runtime invalidation and typed bootstrap denials never replay; expiry
  preserves its existing refresh/no-replay contract. Refresh uses the current token.
- `client-credentials` on normal controller endpoints sends a token, never client
  ID/secret. Only the grant sees credentials. External requests remain credential-free.
- A client-token-only endpoint accepts the ordinary default request; inspect actual
  headers instead of assuming a bearer attempt suppresses the application token.
- Public encrypt/decrypt failures: RFC 7807, legacy structured, and non-RFC JSON;
  preserve status/code/detail/auth/identity/instance/correlation through exceptions
  and `extractErrorInfo`, with body and header correlation fallback.
- Do not invent withheld identity; malformed/oversized error bodies fail safely;
  conflicting body status cannot trigger a retry of a non-401 response.
- Sensitive fields and echoed secrets in title/detail/errors/identity/correlation
  never appear in message, body, structured errors, causes, console or audit/debug
  output. Include non-RFC JSON, plaintext and invalid JSON, using synthetic sentinels.
  Cover large-body audit paths, cyclic/deep data and concurrent requests with distinct
  secrets; assert bounded handling and no cross-request diagnostic contamination.
- Existing 24-caller failed-token coalescing remains one refresh with later retry.
