## Ownership and retained targets

Miso owns `platform-baseline.yaml`, canonical
`scripts/platform-baseline-check.mjs`, common fixtures and parser policy. This plan
owns SDK source/tooling, SDK-local checker adoption, validation and package evidence.
Miso owns consumer pins/locks, application integration and controller image proof.
Other consumers remain with their owner plans; no automatic scope expansion.

- Node 24 is current development/CI. Node 22 is the intended published SDK floor;
  inspect prior support promises before changing engines. Any breaking support
  change needs explicit classification and migration notes, not a claim that
  runtime alignment is inherently non-breaking.
- Node 26 is reported non-blocking readiness only, not adoption.
- Exact pnpm 12.11.2 is inherited Q1, subject to Miso feasibility confirmation.
  No independent fallback; inherited 10.34.6 fallback requires an owner decision.
- Use inherited ^24 Node types in phase 1, down from ^26. Because 24 types alone
  do not prove Node 22 compatibility, inspect changed Node APIs and verify emitted
  code/declarations in clean floor consumers. Use a focused floor-type compilation
  fixture if needed; never widen back to 26 to suppress errors.
- Retain TypeScript 6/Jest 30 already present. Resolve evidenced compatibility
  defects in the current compiler/Jest/ts-jest/ESLint stack with minimal changes.
  Planned broad ESLint/shared-library majors remain a separately detailed phase.
- Adopt baseline B1–B13/Q1–Q4 as applicable: phase-aware checks, strict reviewed
  dependency builds, 4320-minute release age with explicit internal exceptions,
  frozen locks, token-based publishing configuration and provenance.

Targets are inherited planning choices, not verified current registry claims.
Refresh actual version/engine/lock-format support before implementation, including
whether tooling can run on the selected Node 22 patch. No silently weakened floor.

examples: this migration is not a ban on consumer npm use.

parser dependencies, including inherited js-yaml ^4.3.2 for this new installation

its profile; absence of an SDK-owned application image is not a drift failure.

missing-tool failures, no network installs during validation and explicit sibling
parity results. Missing sibling is parity unavailable, not agreement. Local checks
must run without a sibling checkout. Correct shared defects at Miso before syncing.
